### Payment flow (BitElevate, ₹3,999)
Reconstructed from `app/(marketing)/bitelevate/page-*.js`:

```
1. form submit → createBitelevateCashfreeOrder(FormData)
      ← { success, orderId, token, paymentSessionId, environment }
   (no amount in the form, so the price is set server-side ✔)
2. load https://sdk.cashfree.com/js/v3/cashfree.js on demand
   Cashfree({mode: environment}).checkout({paymentSessionId, redirectTarget: "_modal"})
3. verifyBitelevatePayment(token, orderId)
      ← { success, bitElevateCredentials }   on PAID
      ← { orderStatus: "ACTIVE" }            on unpaid (Cashfree order status, so the server queries Cashfree ✔)
4. Return-URL path: on page load, reads ?order_id=…&token=… from the query string
   and calls verifyBitelevatePayment(token, orderId) again.
```

Observations:
- **Login credentials are returned to the browser** (`bitElevateCredentials`) in the action response and rendered on screen.
- The **`token` and `order_id` travel in the URL query string**, and the same page loads GA4 (`G-LK6CQWCWX0`), which records the full page URL by default.
- Fulfilment appears to be **client-triggered** (step 3/4). No sign of a server-to-server webhook can be seen from the client. Whether one exists is **Inferred / unknown**.

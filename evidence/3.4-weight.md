## Waterfall observations

1. **Critical path:** HTML → 2 first-party CSS + 1 third-party CSS (render-blocking) → JS chunks → hydration → template animation sets `opacity: 1` → first paint. The page can't paint before the JS step (see 3.2).
2. **Third-party origin on the critical path:** `fonts.googleapis.com` (CSS) → `fonts.gstatic.com` (woff2) means two extra DNS+TLS handshakes with no `preconnect`.
3. **RSC prefetch fan-out:** 11 background `?_rsc=` fetches. 3 of them hit dynamic routes (`/careers`, `/case-studies`, `/blog/[slug]`), which run uncached serverless renders (250–290 ms each) on every home-page view (see 1.7, 3.1).
4. **Analytics:** GA4 + ads audiences beacons fire during load (no consent gate, see 1.7).

## What is already good
- Root document: **30 ms** server response, 15 KB Brotli. SSG + Vercel edge cache work well.
- First-party static assets: immutable 1-year cache, Brotli, HTTP/2.
- Total Blocking Time 0 ms: the JS is not CPU-heavy, it's just on the critical path.
- CLS 0.

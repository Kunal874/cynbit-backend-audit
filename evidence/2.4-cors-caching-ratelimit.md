# 2.4 / 2.5 CORS, caching, CSRF and rate-limit signals

Sources: headers in `evidence/1.4-headers.txt`, RSC responses from 2.1, error responses in `evidence/2.3-errors.txt`.

## CORS
| Response | `Access-Control-Allow-Origin` | Credentials | Assessment |
|---|---|---|---|
| Static HTML / RSC of static routes (`/`, `/team`, `/services`, 404) | `*` | none | Vercel default for static output. Public content, no cookies. **No risk.** |
| Dynamic HTML / RSC (`/careers`, `/blog`, `/blog/[slug]`) | absent | n/a | Same-origin only ✔ |
| Server Actions | absent (not invoked) | n/a | Next.js ≥ 14 compares `Origin` with `Host` on every action POST and rejects mismatches, which is built-in CSRF protection ✔ (framework behaviour, not observed directly) |

The optional foreign-`Origin` probe from PLAN 2.4 was **skipped**: there are no public JSON API endpoints to test, and the RSC responses already show the configuration.

## Caching
| Route type | `Cache-Control` | Edge | Comment |
|---|---|---|---|
| SSG pages | `public, max-age=0, must-revalidate` | HIT, `Age` ≈ 3 days | correct: edge caches, browser revalidates |
| ISR (`/contact`) | same + `X-Nextjs-Stale-Time: 300` | HIT | correct |
| Dynamic pages + their RSC | `private, no-cache, no-store` | MISS | **every request = serverless render** |
| Unknown `/blog/<slug>`, `/case-studies/<slug>` | `private, no-store` | MISS | **every random slug = a fresh render + lookup** (0.5–1.2 s) |
| `/sitemap.xml` | `public, max-age=0, must-revalidate` | MISS | regenerated per request (`lastmod` = now) |
| Apex 307 redirect | `public, max-age=0, must-revalidate` | n/a | redirect never cached |

`Vary: rsc, next-router-state-tree, next-router-prefetch, next-router-segment-prefetch` is present on all routes ✔, so HTML and RSC variants don't poison each other in shared caches.

## Rate limiting
- **No rate-limit headers** (`RateLimit-*`, `X-RateLimit-*`, `Retry-After`) on any response, including the dynamic routes and error paths.
- Vercel's platform DDoS mitigation sits in front of the app regardless. Whether a Vercel WAF rule or app-level limiter protects the **Server Actions** can't be observed without sending bursts, which is out of scope.
- Combined with no CAPTCHA (1.6) and uncached unknown-slug lookups (2.3), the cheapest ways to cost Cynbit money or fill their DB are: (1) repeated `POST`s to the lead/newsletter/order actions, and (2) `GET /blog/<random>`. Reported as **Inferred**.
